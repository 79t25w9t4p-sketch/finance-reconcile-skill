## 标题与封面

标题：**客户又发来新明细，上次核实过的还要再查一遍？**

封面：上行“更新明细，又要重新对账”；下行“沿用旧意见，先看新增和变化”。

## 短视频分镜

| 镜头 | 画面 | 口播/字幕 |
|---|---|---|
| 问题 | 上次已填写的复核表，与本次更新明细 | 两份表又更新了。上次已经处理过的异常，哪些可以沿用，哪些要重新查？ |
| 输入 | 已准备好的Agent里给新文件、旧配置和上次工作簿 | 这个Skill面向已经在用本地Agent的人。第一次确认规则，之后可以复用。只需Python和Excel读写组件，首次仍要检查环境。 |
| 变化 | 本次重点中的B、D | 虚构示例里，B金额变了，要重新复核；D是新增事项。这次重点先列出这两项。 |
| 沿用 | 查看A的旧意见、C的历史记录 | A没变，沿用已解决。C本次没出现，留在历史，不自动当成结案。模拟处理意见由脚本填写。 |
| 后续工作 | 点击处理入口，再打开跟进清单 | 重点页只读，点击回到原记录填写意见。旧的未解决事项仍在跟进清单里，不会因没有新增就漏掉。 |
| 入口 | GitHub首页及备用Agent入口 | 项目和可复现示例在GitHub，把入口交给有文件和脚本能力的Agent即可试用。欢迎记录第一次卡点和第二次是否愿意继续用。 |

## 小红书文章草稿

**客户又发来新明细，上次核实过的还要再查一遍？**

重复对账麻烦的一部分，是新表来了，还要重新筛异常、搬上次的意见，再整理一份跟进清单。

我用AI协助做了一个客户对账Skill，给已经在用本地Agent、反复核对固定格式明细的财务助理试用。第一次确认共同单号和金额列，保存规则；之后交新明细与已填写的上次复核表。

配图是虚构示例：A未变，沿用已解决；B金额变化，保留旧意见并要求重新复核；新增D，进入本次重点；C没出现，留在历史。这次先看B、D，再通过处理入口回到原记录填写。旧的未解决事项也会继续留在跟进清单里。

只需要Python和openpyxl，不再需要Node；首次仍需环境准备。两表需要有共同业务编号、同一业务范围和金额口径，编号重新使用的新业务不能沿用旧意见。当前不处理无共同编号的流水或多笔回款核销。

项目、示例和教程放在GitHub。目前还没有真实用户节省时间的测量。更想知道的是：你第一次能不能拿到可用结果，第二次是否愿意继续用，具体还有哪一步要重做。
