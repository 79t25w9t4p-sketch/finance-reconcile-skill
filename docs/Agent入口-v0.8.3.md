## 2. 按用户的任务运行

首次用已有Python运行scripts/doctor.py；只需Python 3.9+和openpyxl>=3.1,<4，不需要Node。缺组件时说明具体缺项和准备位置；用户已授权项目独立环境补必需库时，在该环境安装requirements.txt。缺Python时说明方案，不直接修改系统环境。已成功运行则不重复完整检查。

**已有两份实际文件**：按SKILL.md用suggest.py先检查明细页和表头，唯一可见候选才建议位置，多候选或隐藏候选由用户确认；将确认的工作表和表头行随字段映射完整传给workflow.py，核对共同编号，只集中确认未明确或冲突的字段、客户范围、期间、币种、金额口径和明细粒度。已给出的信息直接采用。确认后用workflow.py核对并保存规则；不先运行模拟示例，也不要求先安装到用户技能目录。

**没有文件，用户只想试效果**：运行examples/month_end_demo.py到新工作目录。全部虚构，预期8个编号组、3组指定金额一致、5组待核实，SH-002差50.00。报告实际运行结果，不能只复述预期值说成功。用户要求看换表复用时才运行examples/workflow_demo.py，模拟意见不得称为真实核实。

默认交付复核工作簿.xlsx和跟进清单.xlsx，在对话里简述待核实数量、分类和下一步。读取已生成的本次待办摘要.txt帮助概述，但不默认把它和全部技术记录一并交付。CSV、JSON及哈希记录留在结果目录，按需提供；脚本输出文件不删除。

复核表汇总和跟进表使用说明均标明原文件、实际工作表及表头行，结合事项来源行回查。内部表的本次重点只读，处理入口链接到原记录黄色列；跟进反馈目前需整理回内部表。手动修改状态不会实时更新生成的汇总和跟进表，重跑后更新。金额差异不是错账结论；本次未出现不是已解决。
