# 当前改良原则：先让最短流程成立

用户假设：已经在用本地Agent、反复核对固定格式客户明细的财务助理。具体任务是比较同一客户、同口径、有共同业务编号的两份明细，整理可回查的差异与跟进清单。这是待真实试用验证的假设。

## 当前优先级

现有核对、异常保留、跟进清单和旧意见沿用，已能组成一次试用。先验证：用户交两份表、确认必要字段和业务口径，能否拿到直接可用的结果，以及是否减少其原来的操作。

本次只修正已观察到的流程阻碍：首页曾要求先跑示例和安装，再换自己的表；改为有文件直接核对，无文件才选示例。默认交付两份Excel，其余技术记录按需查看。已给出的口径不再重复询问。

暂不开发自动挑选历史文件、客户档案或反馈自动导入。只有真实试用反复出现对应阻碍，且能够说明节省的步骤和新增维护成本时，才考虑实现。脚本出错或输出无法使用则直接修复，不等到推广后。

## 怎么判断是否值得继续用

请实际执行这类工作的用户，按自己的原流程和工具流程完成相同范围任务：

- 原流程可能已有Excel模板或其他工具，不能人为换成低效的逐行核对来夸大收益。
- 比较首次准备、修表、确认、核对及整理收尾的总成本；未计时写“未记录”。
- 记录拿到结果后仍需手动补的步骤、错误与卡点。只有重复使用的用户才验证第二批明细能否独立完成。

模拟演示和自动测试用于核验运行行为；不证明需求成立，也不证明实际省时。具体记录见[试用反馈](试用反馈.md)。目前没有真实采用率或节省时间数据。

## 保留的边界

共同编号、客户范围、期间、币种、金额含义及明细粒度需确认。若编号被新业务重复使用，不能继承旧意见。差异是待核实线索，不等于错账；本次未出现不等于结案。

当前不提供无共同编号的银行流水匹配、多笔回款核销或跨粒度汇总。不因扩展功能更容易宣传就扩大范围。
