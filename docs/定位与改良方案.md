# v0.8 定位与改良方案

首批目标：**已经在用能读写本地文件、执行Python的Agent，反复核对固定格式客户明细，不想维护脚本的财务助理。** 这是待真实试用验证的用户假设，不代表已完成访谈。

## 具体工作时刻

客户再次发来更新明细，我方也有新的导出。上次已经核实过部分异常；这次要沿用规则和处理意见，先找新增、内容变化和仍未解决的事项，整理跟进清单。

输入仍需有共同业务编号、同一客户范围、对应期间与币种、同一金额口径和明细粒度。编号作用域必须一致；若编号按月重用或换客户，不沿用旧意见。配置不能证明业务范围相同。

## 已完成的改进

| 使用障碍 | v0.8处理方式 |
|---|---|
| 同时准备Node和Python | 全部运行脚本统一Python，只保留openpyxl作为Excel依赖 |
| 查出全部差异后，还要从旧事项里找这次该做什么 | 本次重点视图优先展示首次待核实、新增与变化项 |
| 已解决事项又重新处理，旧意见重复搬 | 内容未变才沿用状态和意见，变化项要求重新复核 |
| 同时填写两处意见容易不一致 | 本次重点只读，点击处理入口回到唯一可编辑原记录 |
| 没有新增就误以为完成 | 摘要单独列旧事项仍待跟进；跟进清单保留全部未解决事项 |
| 看不到测试证据与反馈路径 | 首页CI徽章、验证记录、换表复用示例、自愿试用反馈模板 |

旧配置和复核工作簿格式继续支持。跟进反馈仍需写回内部表；手工修改状态不会实时刷新生成的汇总和跟进清单。

## 首次与第二次验证

首次成功标准：目标用户能获取运行文件、使用已有Python或明确准备缺项、确认字段并打开可使用的结果。记录真实卡点与准备成本。

第二次成功标准：同一业务范围内能够复用规则、沿用未变化的旧意见，并正确区分新增、变化、仍待跟进和本次未出现。询问下次是否愿意继续使用，不能只用演示计数代替这个答案。

具体记录见[试用反馈](试用反馈.md)。未计时写“未记录”；模拟演示、自动测试通过、浏览量和星标均不能证明实际节省时间。目前没有公开的真实采用率或节省时间测量。

## 范围与依据

当前聚焦同口径明细比较，尚不提供无共同编号的流水匹配、多笔回款核销或跨粒度汇总。

[金蝶销售订单执行明细手册](https://help.open.kingdee.com/dokuwiki_std/doku.php?id=%E9%94%80%E5%94%AE%E8%AE%A2%E5%8D%95%E6%89%A7%E8%A1%8C%E6%98%8E%E7%BB%86%E8%A1%A8)区分发货、出库、应收、开票与收款；本版不能直接把不同环节的金额差额当作错账。以共同业务单号作为入口是基于当前能力的选择，市场需求仍待验证。

自然语言接入方式参考[finance-copilot-skills](https://github.com/cxtx/finance-copilot-skills)，代码独立实现。Codex技能目录依据[官方文档](https://learn.chatgpt.com/docs/build-skills#where-codex-loads-local-skills)。首次用户需要已有Agent基础，不能宣传为任意聊天窗口粘贴即用。
