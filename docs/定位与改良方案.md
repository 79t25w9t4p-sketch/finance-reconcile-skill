# v0.7 定位与改良方案

## 决定：先解决一个工作时刻

首批目标是中小商贸公司的财务助理或应收岗位新人，第一次独立处理客户月末明细核对。触发时刻是：**客户发来Excel，说金额对不上；我方也有导出的明细，要找出具体该核实的单据。**

“刚接触AI”描述使用经验；真正决定是否需要本工具的是手头有这项重复任务。暂不按年龄、公司规模数字或工作年限假设需求。这是待试用验证的定位，不代表已经访谈或验证了市场。

## 人群进一步拆分

| 维度 | 首批定位 | 为什么 |
|---|---|---|
| 岗位 | 正在做客户明细对账的财务助理/应收新人 | 能明确指出原来怎样核对与要交什么成果 |
| 触发 | 月末收到客户异议或双方明细 | 有眼前任务，能直接试用 |
| 输入 | 同一客户、同一期间与币种；双方共用送货单号；逐单金额口径一致 | 现有精确匹配可接手机械步骤 |
| 技能 | 会下载、打开Excel；不想写代码或反复拼公式 | 需要助手带做首次体验 |
| AI基础 | 愿意在能执行本地文件的AI助手中准备一次环境 | 当前Codex流程仍有门槛，不能宣传成任意聊天窗口即用 |
| 交付 | 内部复核表＋待核实跟进清单 | 把“查出差异”接到后续工作 |

先用单客户场景；多客户表可按确认的共同客户标识＋单号核对，但客户采购表的“供应商”常指我方，并不等于我方表中的“客户”。双方自有编码也不一定相同。不得只看列名就联接。

## 痛点与产品承诺

| 痛点 | 本版接手的步骤 | 仍由人确认 |
|---|---|---|
| 不知道该对应哪列 | 表头建议；有歧义才补问 | 两列是否真指同一业务 |
| 每次重新拉公式与筛选 | 确定性核对和异常分类 | 期间、币种、含税与逐单口径 |
| 查出差异，还得另抄跟进表 | 自动输出待核实清单及检查建议 | 差异原因、联系对象、应否调整账目 |
| 新表来了，旧意见又要搬 | 配置复用；仅未变化记录沿用意见 | 变化项重新核实 |

对外承诺：**确认规则后，自动整理有共同单号的两份明细，交付可回查的差异及跟进清单。**

不把缺失数据当零，不把相近金额猜成匹配，不承诺自动判断责任方。无共同编号、多笔回款核销、截图/PDF识别与跨粒度汇总目前不在这一体验范围内。

## 已执行的改良

1. 首页从宽泛岗位列表改成具体触发场景，提前说明适用表格。
2. 用同一业务示例贯穿教程、真实生成的Excel产物及分享稿。
3. 新增只读环境检查，已有运行时可复用；缺项时说明下一步。
4. 可先在下载目录显式读取技能试用，成功后再安装到官方技能目录。
5. 识别送货单号和含税/未税金额的常见表头；多个金额列仍要求选择。
6. 新增独立跟进清单：仅含未处理项，保留来源行、原金额与核实建议；不导出内部意见。

跟进表反馈不会自动写回内部复核表；手工状态修改也不会实时刷新汇总和跟进表。教程明确这两个现有限制，避免用户以为已经联动。

## 首轮传播与验证

先发一个问题导向的演示：**“客户说账对不上，你该先查哪几笔？”** 展示原表、一次运行与跟进产物，再给完整教程链接。视频和文章都标明模拟数据、首次环境准备与适用前提。

此仓库仅提供稿件，账号发布由作者决定。试用反馈应记录：

- 看到标题的人是否正遇到这个场景；原本用什么办法。
- 是否看懂适用条件、找得到开始入口。
- 从第一次打开教程到拿到结果，具体卡在哪一步。
- 输出是否能直接接入复核与跟进，是否还需大量重抄。
- 换第二份表时是否愿意再次使用；哪些格式仍需人工整理。

浏览量低只说明曝光或标题入口尚待验证，不能单独判断产品价值。有人点开却无法开始，应优先改入口；有人用完却不愿重跑，应优先查成果是否接得上工作。真实耗时只在取得自愿反馈后测量，当前不写节省比例。

## 依据与不确定性

[金蝶销售订单执行明细手册](https://help.open.kingdee.com/dokuwiki_std/doku.php?id=%E9%94%80%E5%94%AE%E8%AE%A2%E5%8D%95%E6%89%A7%E8%A1%8C%E6%98%8E%E7%BB%86%E8%A1%A8)将发货、出库、应收、开票、收款区分为不同环节，并说明收款数据与核销的关系。这支持将本版限定为同口径明细比较，不能直接把销售金额与回款金额差额当作错账。以“双方共用送货单号”作为首个体验入口，是本项目基于能力边界的推断，尚无真实需求验证。
