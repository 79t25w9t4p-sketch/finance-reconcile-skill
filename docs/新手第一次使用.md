# 第一次使用：有文件就直接核对

面向已经在用能读写本地文件、执行Python的Agent的人。需要Python 3.9+和openpyxl；不需要Node。普通聊天窗口不能直接执行本机脚本。

## 1. 按手头的情况开始

**已有两份明细**：把文件放在自己指定的工作目录，按[首页的直接核对指令](../README.md#已经有两份表直接核对)提供两份路径及已知的客户、期间、币种和金额口径。未知信息写“不知道”，助手集中确认必要缺项；不要求先跑示例。

**还没有文件，只想看效果**：先打开[跟进清单示例](../examples/月末客户对账/跟进清单.xlsx)。结果适合自己的工作，再用[首页的示例指令](../README.md#还没有文件先看或运行示例)运行虚构文件。

两条路径都使用[Agent接入入口](https://cdn.jsdelivr.net/gh/79t25w9t4p-sketch/finance-reconcile-skill@main/docs/Agent入口-v0.8.4.md)。首次在任务目录获取和试用；已安装则直接调用，不重复下载或跑示例。GitHub获取失败时尝试入口指定的备用文件源；都失败则说明具体卡点。

## 2. 确认对应方式

助手先定位明细页与表头，再建议共同编号和金额列，再确认尚未明确的业务口径。两份表必须对应同一范围、同一币种、可比较的金额含义和明细粒度。不能把两边各自系统的订单号当共同单号，也不能把销售额、应收余额和回款额直接相减。

发现疑似合计/小计或重复打印表头时，助手先确认它们是否为明细；确认排除后在新副本整理，记录来源位置，保留原文件。底层脚本不自动删行。

已提供的信息直接采用，不重复问。多个金额候选、编号关系或客户范围不明确时，只确认这些问题；不知道就先停止核对，不为了运行随便选择。

优先复用已有Python。首页指令只授权在本项目独立环境补必需Python库；先说明缺项和准备位置，不做系统级安装。其他请求按其已有授权处理；缺Python时先说明方案，不直接改系统环境。

## 3. 看结果，核实事实

默认拿到两份Excel：

- **复核工作簿.xlsx**：先看汇总和本次重点。点击处理入口，到待处理页黄色列填写状态与内部意见；保留原表头和隐藏标识列。
- **跟进清单.xlsx**：按编号、两边金额和来源行回查原始表。检查接收范围后可用于业务核实；收到反馈后，把确认结果填回内部表。

助手在对话里概述待核实数量和下一步。文本摘要、CSV、JSON及哈希记录留在结果目录，排查时再看。两个Excel都是生成时快照；手动修改状态不会实时刷新统计，重跑后更新。

示例数据全部虚构：8个编号组，3组指定金额一致、5组待核实；SH-002比较2350.00与2300.00，差50.00。清单提供检查方向，不声称知道差异的真实原因。[示例说明](../examples/月末客户对账/说明.md)

## 4. 确认有用以后再安装

对Agent说：

> 把刚才试用成功的完整Skill安装到当前宿主的用户技能目录，以后继续使用，不重复跑示例。

Codex路径是 `~/.agents/skills/finance-reconcile/`，Windows使用对应用户目录；其中直接包含SKILL.md、scripts和examples。已有同名版本先说明，不动其他技能。不复制.git、虚拟环境、缓存或真实业务资料。[官方目录说明](https://learn.chatgpt.com/docs/build-skills#where-codex-loads-local-skills)

下次交两份新明细及已填写的上次复核表，要求沿用确认过的规则。未变化事项可沿用意见，变化项重新复核，旧未解决项仍要跟进。[换表复用说明](../examples/换表复用/说明.md)

配置不证明业务范围相同。换客户或编号按月重新使用时另建工作目录，不继承旧意见。

## 常见卡点

| 情况 | 处理方式 |
|---|---|
| 未找到Python / openpyxl | 先检查现有运行时，说明缺项及准备位置 |
| 多个工作表或非首行表头 | 自动检查前20行；多个候选或隐藏页需确认，未识别时指定明细页及表头行 |
| 合计/小计或重复打印表头 | 确认行类型，由Agent制作新副本；不改原文件 |
| 只有样式的空尾列 | 自动忽略；存在数据的无名列仍需补齐表头 |
| 多个金额列或无共同编号 | 集中确认对应关系，不能猜 |
| 原表含公式 | 在原软件重算后导出值 |
| 表头与旧配置不同 | 展示变化，确认后另存配置 |
| 重复编号很多 | 确认是否粒度不一致，本版不自动合并 |
