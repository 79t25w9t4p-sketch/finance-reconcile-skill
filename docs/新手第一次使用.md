# 第一次：从示例到自己的两份表

面向已经在用本地Agent、反复核对固定格式客户明细的财务助理。先用虚构文件拿到结果，确认适合自己的工作，再放入真实文件。

## 0. 先看结果，判断值不值得准备

下载[跟进清单](../examples/月末客户对账/跟进清单.xlsx)，打开“待核实事项”。如果你想要的就是一张列出待查单号、两边金额、来源行及核实问题的表，继续下面的步骤。

这套教程目前提供Codex本地运行方式；只需要Python 3.9+和openpyxl，不需要Node。项目不收取代码费用，AI宿主的账户与费用另行准备。首次环境准备仍是门槛，单独粘贴一段提示词不会运行本机脚本。

## 1. 复制安装指令，让 Agent 获取 GitHub 仓库

打开[首页的完整 Agent 指令](../README.md#复制这段话交给-codex)，把整段文字复制给能够联网、读写本地文件并执行脚本的Codex。它会获取完整仓库、检查环境、跑示例并安装技能，不要求你自己下载或拼命令。

如果只想先试用，可以补充“先不安装到用户技能目录，只运行示例”。已经安装过则直接调用，不重复获取仓库。

GitHub页面在你的浏览器打不开时，可把首页的备用入口交给Agent。按[Agent接入说明](https://cdn.jsdelivr.net/gh/79t25w9t4p-sketch/finance-reconcile-skill@main/docs/Agent入口-v0.8.0.md)，先尝试GitHub，再使用列出的jsDelivr文件源，获取清单中的完整运行文件并校验，示例Excel由脚本本地生成。代码仍来自这个GitHub项目，不需要用户自己下载安装包。仅看到网页文本不等于已获取完整技能；两条来源都失败时报告具体卡点。

首页指令授权在项目独立虚拟环境安装必要Python库，优先复用已有运行时。缺Python时先说明安装方式；不要悄悄改系统环境。没有本地文件或脚本能力的普通聊天界面不能直接执行这套流程。

## 2. 对照这次应该得到什么

示例全部虚构，假定同一客户、2026年9月、人民币、逐送货单含税金额。

- 我方8行、客户7行，共8个编号组。
- 3组指定金额一致，5组待核实。
- SH-002金额差50.00；SH-004只在我方，SH-008只在客户。
- SH-005我方同号两行，需确认是否一单多行；SH-006缺金额。

“复核工作簿.xlsx”供你内部记录；“跟进清单.xlsx”只有待核实项。打开跟进表看SH-002：比较2350.00与2300.00，再按来源行回到两份原表核实。清单给出检查方向，不声称知道真实差异原因。

## 3. 换成自己的文件

把自己的两份文件放到一个新工作目录，并说明两表各是什么。可以复制并替换下面文字：

> 左表是我方明细，右表是客户发来的明细，文件分别是「文件路径」和「文件路径」。这次是「客户」的「期间」，币种「币种」。我希望比较「含税/未税金额」，两表「每张单一行/其他粒度」。先检查两表有无共同业务单号，给我建议的对应方式；不明确的地方集中问我。确认后输出复核表和跟进清单，保存这次规则。

不知道编号或口径时直接说不知道，不需要为了运行而随便确认。客户表的内部采购单号与我方内部销售单号可能不同；“供方送货单号”是否对应我方送货单也要确认。

## 4. 用结果继续处理

先看内部“本次重点”页，点击“处理入口”到“待处理”页的黄色列填写状态和意见。“本次重点”是只读视图，避免两处意见不一致。重复编号、空编号和无效金额先回查原始表。保留隐藏标识列及原表头，便于下次沿用意见。

跟进清单供你检查后用于核实：不含内部意见，但仍含业务编号和金额。只在应接收该客户信息的范围内使用，不把公开仓库示例入口当成上传真实账单的位置。当前没有自动发送或自动导入跟进反馈；收到反馈后把确认结果填回内部复核表。

## 5. 下次少说一点

> 按上次保存的规则核对这两份新文件，沿用这份上次复核工作簿的处理意见，输出到新的目录。

未变化的记录可沿用状态；金额、描述或匹配关系变化时需重新复核。历史条目不等于结案。

这次收到的`本次待办摘要.txt`分别列出本次重点、旧事项仍待跟进、已解决沿用和本次未出现数量。没有新增不代表全部完成：旧的未解决事项仍在跟进清单里。可让助手运行`examples/workflow_demo.py`，或查看[换表复用示例](../examples/换表复用/说明.md)。

旧意见只用于同一客户、同一业务编号作用域。若换了客户，或编号每月会重新从头使用，另建工作目录，不把旧意见带到新业务里。配置保存列的对应方式，不能证明客户或期间相同。

首页指令已包含试用成功后的技能安装。目录层级依据[官方说明](https://learn.chatgpt.com/docs/build-skills#where-codex-loads-local-skills)；技能未出现时检查层级，并按官方说明重启。原有同名版本先说明再更新，其他技能不动。

## 卡住时怎么处理

| 看到的问题 | 让助手具体处理什么 |
|---|---|
| GitHub页面或仓库获取失败 | 按Agent接入说明尝试列出的备用文件源；都失败则报告卡点，不保证网络一定可达 |
| 未找到Python / openpyxl | 检查已有运行时；缺什么、准备装哪里要说清楚 |
| 有多个工作表或表头不在第一行 | 指定明细页及表头行，不把标题当列名 |
| 多个金额列 | 确认同一个含税/未税口径；不要猜 |
| 原表含公式 | 在原软件重算后导出值，再核对 |
| 表头与旧配置不同 | 展示变化，确认后另存配置 |
| 重复很多 / 找不到共同编号 | 检查是否逐商品而另一边逐单，或两系统编号不同；先确认关系 |
| 自己改了状态，汇总没变化 | 汇总和跟进表是生成快照，重跑后更新 |

这些步骤是当前实现的操作路径，不代表已经由真实新手试用验证。反馈时给列名、错误描述和最小虚构样例即可。

第一次试用后，按[试用反馈](试用反馈.md)记录是否拿到可用结果、卡点和第二次是否愿意继续用；没有测量的时间写“未记录”，不猜节省比例。
