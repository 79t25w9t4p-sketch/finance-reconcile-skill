# 验证它是否值得继续用

请由正在反复核对固定格式客户明细、已经在用本地Agent的人实际试用。模拟演示证明运行路径，不代表真实工作收益。

## 第一次：能否拿到可用结果

- 你平时核对的两份表是什么？只描述用途与列名，不提供真实客户、单号、金额或文件。
- 使用什么Agent、操作系统？是否已经有可用Python？
- 是否得到能打开的复核工作簿和跟进清单？卡在获取、依赖、字段确认、运行，还是看不懂结果？
- 从开始到拿到可用结果用了多久？没有计时写“未记录”。安装等待与实际核对时间分开记录。

## 第二次：是否减少重复步骤

使用同一业务范围、编号作用域一致的更新明细，以及已填写意见的上次复核工作簿。不要为了测试把另一个客户或重复使用编号的新业务套进去。

- 规则是否直接复用？是否还要重复解释已经确认过的字段？
- 未变化的已解决事项是否沿用？变化项是否明确要求重新复核？
- “本次重点”是否让你更快找到这次该处理的事项？旧的未解决事项有没有遗漏？
- 下次是否愿意继续使用？如果不愿意，主要原因是什么？

需要比较时间时，记录自己的原流程和工具流程实际完成同一范围任务的时间，保留首次准备成本；不要根据模拟条数推算节省比例。

## 如何反馈

通过[GitHub试用反馈入口](https://github.com/79t25w9t4p-sketch/finance-reconcile-skill/issues/new?template=first-use.md)提交自愿反馈。也可以只把以上答案留在自己的本地笔记里，不必公开。

公开反馈只包含流程描述、列名、错误信息和最小虚构样例。项目不收集账单、不自动上报使用情况，不要求填写联系方式。
