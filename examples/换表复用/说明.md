# 更新明细后，先看这次需要处理的两项

全部为虚构数据。同一客户、同一编号作用域的更新明细，不是把编号重复使用的新业务当成旧事项。

运行`python examples/workflow_demo.py 新目录`可复现两个批次：首次A、B、C各有1.00差额；示例脚本在上次复核表填写“已解决”和模拟意见。随后A不变、B金额变化、C未出现、新增D。

| 编号 | 更新后 | 用户接下来做什么 |
|---|---|---|
| A | 内容未变，沿用已解决和旧意见 | 不进入本次重点和跟进清单，仍保留原记录 |
| B | 金额变化，旧意见保留，需重新复核 | 进入本次重点；点击处理入口回查并更新状态 |
| C | 本次未出现 | 留在历史记录，不自动判定结案 |
| D | 新增金额差异 | 进入本次重点，首次核实 |

因此这次重点2项：新增1项、重新复核1项；已解决沿用1项、上次记录本次未出现1项。预生成结果见[本次复核工作簿](本次复核工作簿.xlsx)、[本次跟进清单](本次跟进清单.xlsx)和[本次待办摘要](本次待办摘要.txt)，上次已填写的示例见[上次复核工作簿](上次复核工作簿.xlsx)。

这里的模拟意见由示例脚本填写，不能当作实际业务核实结果。这些计数展示状态处理规则，不代表真实节省时间。
